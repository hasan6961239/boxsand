# NOVA HOST — المعمارية

## المبدأ الحاكم

**عملية واحدة (Monolith)، صفر تبعيات، حدود أمنية واضحة.**

المشروع شخصي والخادم هاتف. كل خدمة إضافية تعني ذاكرة أكثر، وبطارية أكثر، وعطلاً
محتملاً أكثر، وصيانة أكثر. لذلك: عملية Node واحدة تفعل كل شيء، لكنها مقسّمة داخلياً
إلى طبقات نظيفة يمكن فصلها لاحقاً دون إعادة كتابة.

## لماذا منفذان؟

هذا قرار أمني وليس تنظيمياً.

المواقع التي ترفعها تحتوي **JavaScript عشوائياً**. لو قُدِّمت من نفس الأصل (origin)
الذي تُقدَّم منه لوحة التحكم، لاستطاع سكربت في أي موقع مرفوع أن ينادي
`fetch('/api/projects', {credentials:'include'})` ويتحكم بمنصتك كاملة.

سياسة الأصل الواحد (Same-Origin Policy) في المتصفح تفصل حسب **(البروتوكول، المضيف، المنفذ)**.

- في وضع النطاقات: `panel.example.com` و `site.example.com` مضيفان مختلفان → معزولان.
  وكوكي الجلسة **host-only** (بلا `Domain=`) فلا يُرسل إلى النطاقات الفرعية أصلاً.
- في وضع الشبكة المحلية: لا توجد نطاقات فرعية، لذلك نستخدم **منفذاً مختلفاً**
  (8081) وهو أصل مختلف بحكم التعريف. الحدّ الأمني محفوظ بلا DNS وبلا إنترنت.

المنفذ 8081 لا يملك أي مسار API — الموجّه الخاص به لا يعرف حتى بوجودها.

## تدفّق الطلب

**طلب إلى لوحة التحكم:**
```
http.Server(8080) → securityHeaders → requestLog → router
  → /api/*  → rateLimit → session → csrf → handler → respond.json
  → غير ذلك → هل المضيف موقع مستضاف؟ نعم → sites.serve
                                      لا  → static(frontend/)
```

**طلب إلى موقع مستضاف:**
```
http.Server(8081) → securityHeaders(site) → sites.resolve(host, path)
  → قراءة current_deployment_id → static(deployments/<id>/) → stream
```

## القابلية للنقل لاحقاً

لا شيء في الكود مرتبط بأندرويد في المسار الحرج:
- المسارات كلها نسبية إلى `DATA_DIR` وتُحلّ عبر `path.resolve`.
- لا استدعاء لأمر نظام إلا في `services/stats.js`، وكلها داخل `try/catch`
  وتُرجع `unavailable` بدل الانهيار.
- نقل المشروع إلى Raspberry Pi أو VPS أو Windows = نسخ المجلد + `npm start`.

ولأن طبقة البيانات معزولة في `db/repo/`، فإن الانتقال من SQLite إلى PostgreSQL
مستقبلاً يمس هذا المجلد وحده.
