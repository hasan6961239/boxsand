# الشبكة والوصول من الإنترنت

ثلاثة أوضاع، والمنصة تدعمها كلها في نفس الوقت بلا إعادة إعداد.

---

## MODE A — الشبكة المحلية

**التكلفة: صفر. المتطلبات: لا شيء. يعمل بلا إنترنت.**

```
http://192.168.1.XX:8080          لوحة التحكم
http://192.168.1.XX:8081/s/slug/  الموقع
```

يعمل من اللابتوب ومن الآيفون ومن أي جهاز على نفس الواي فاي. هذا هو الوضع الذي
يجب أن تبدأ به وتتأكد أن كل شيء يعمل قبل التفكير في الإنترنت.

### لماذا منفذان؟

لأن **المنفذ المختلف = أصل (origin) مختلف** في المتصفح. المواقع التي ترفعها
تحتوي JavaScript؛ لو قُدِّمت من نفس أصل لوحة التحكم لاستطاع سكربت في أي موقع
مرفوع أن ينادي الـAPI بجلستك ويتحكم بمنصتك.

### قيد يجب أن تعرفه في وضع المسار

الموقع المقدَّم على `/s/slug/` يعمل جيداً إن كانت روابطه **نسبية**
(`css/style.css`). المنصة تحقن `<base href="/s/slug/">` تلقائياً لتصحيحها.

لكن الروابط **المطلقة** (`/css/style.css`) لا يصلحها أي `<base>` — هذا قيد في
HTML نفسه وليس في المنصة. تعاملنا معه بحيلة: إن جاء طلب مطلق ومعه ترويسة
`Referer` تشير إلى موقع، نعيد التوجيه إلى المسار الصحيح. تعمل في أغلب الحالات
لكنها ليست مضمونة.

**الحل الصحيح هو استخدام اسم مضيف بدل مسار.** طريقتان مجانيتان:

**١. على اللابتوب — `*.localhost` يعمل بلا أي إعداد:**
```
http://my-site.localhost:8081
```
Chrome و Safari و Firefox كلها تحلّ أي شيء ينتهي بـ`.localhost` إلى 127.0.0.1.

**٢. على الشبكة المحلية — خدمة DNS عامة مجانية:**
```
http://my-site.192-168-1-14.sslip.io:8081
```
`sslip.io` (و`nip.io`) تحلّان أي عنوان مكتوب في اسم النطاق إلى ذلك العنوان.
مجانية، بلا تسجيل، وتعطيك نطاقات فرعية حقيقية على شبكتك المنزلية. **لكنها تحتاج
إنترنت لعمل استعلام DNS** — فهي لا تعمل عند انقطاع الخدمة.

المنصة تتعرف على الشكلين تلقائياً، لا إعداد مطلوب.

## MODE B — نفق سريع (رابط مؤقت)

**التكلفة: صفر. المتطلبات: لا حساب، لا نطاق.**

```bash
pkg install cloudflared
scripts/tunnel.sh quick
```

يطبع رابطاً مثل:
```
https://fancy-words-1234.trycloudflare.com
```

يعمل من أي مكان في العالم، بـHTTPS، فوراً.

**القيود — وكلاهما حقيقي:**
- الرابط **عشوائي ويتغيّر مع كل إعادة تشغيل**. لا يصلح كعنوان دائم.
- كلاودفلير نفسها توثّق أن الأنفاق السريعة **غير مناسبة للإنتاج**.
- لا يمكن الحصول على نطاقات فرعية لكل مشروع.

ممتاز لـ: أن تُري أحدهم موقعاً الآن، أو أن تختبر أن النفق يعمل قبل شراء نطاق.

> **لا تنزّل `cloudflared` من صفحة إصدارات GitHub.** تلك النسخ مبنية لـglibc
> ولن تعمل على أندرويد. استخدم `pkg install cloudflared` فقط.

## MODE C — نفق مُسمّى + نطاقك

**التكلفة: ثمن النطاق فقط (١٠–١٥ دولاراً سنوياً). كل ما عداه مجاني.**

```
https://panel.example.com        لوحة التحكم
https://my-site.example.com      كل مشروع بنطاق فرعي
```

### لماذا يحتاج نطاقاً؟

لأن النفق المُسمّى يربط اسم مضيف حقيقياً بالنفق، واسم المضيف يجب أن يكون في
منطقة DNS تملكها على كلاودفلير. لا توجد طريقة مجانية للحصول على اسم ثابت
بنطاقات فرعية. هذا هو **الشيء الوحيد غير المجاني في المشروع**.

### الإعداد خطوة بخطوة

**١. حساب Cloudflare (مجاني)**

سجّل على [dash.cloudflare.com](https://dash.cloudflare.com).

**٢. أضف نطاقك**

اشترِ نطاقاً (كلاودفلير نفسها تبيع بسعر التكلفة تقريباً)، أو انقل نطاقاً تملكه.
غيّر خوادم الأسماء (nameservers) إلى ما تعطيك كلاودفلير، وانتظر التفعيل.

**٣. سجّل الدخول من الهاتف**

```bash
cloudflared tunnel login
```

سيطبع رابطاً. افتحه في متصفح الهاتف، اختر نطاقك، وامنح الإذن.

**٤. أنشئ النفق**

```bash
cloudflared tunnel create novahost
```

يطبع معرّف النفق (UUID) ويحفظ ملف اعتماد في `~/.cloudflared/<UUID>.json`.

> **هذا الملف سرّ.** لا ترفعه إلى Git إطلاقاً. ملف `.gitignore` في المشروع
> يستثني `.cloudflared/` مسبقاً.

**٥. اكتب ملف الإعداد**

```bash
nano ~/.cloudflared/config.yml
```

```yaml
tunnel: novahost
credentials-file: /data/data/com.termux/files/home/.cloudflared/<UUID>.json

ingress:
  # لوحة التحكم على المنفذ 8080
  - hostname: panel.example.com
    service: http://localhost:8080

  # كل النطاقات الفرعية الأخرى هي مواقع، على المنفذ 8081
  - hostname: "*.example.com"
    service: http://localhost:8081

  # القاعدة الأخيرة إلزامية
  - service: http_status:404
```

**ترتيب القواعد مهم:** كلاودفلير تطابق من الأعلى للأسفل، فسطر `panel` يجب أن
يسبق سطر `*`.

**٦. وجّه الـDNS**

```bash
cloudflared tunnel route dns novahost panel.example.com
cloudflared tunnel route dns novahost "*.example.com"
```

السجلات الموكَّلة بحرف البدل (proxied wildcard) **متاحة على الخطة المجانية**
منذ 2022.

**٧. اضبط `.env`**

```ini
PANEL_HOST=panel.example.com
SITES_DOMAIN=example.com
PUBLIC_URL=https://panel.example.com
TRUST_PROXY=true
SECURE_COOKIES=auto
```

ثم `scripts/restart.sh`.

**٨. شغّل النفق**

```bash
scripts/tunnel.sh run novahost
scripts/tunnel.sh status
```

**٩. لتشغيله تلقائياً مع الإقلاع**

أضف سطراً إلى `~/.termux/boot/novahost` قبل السطر الأخير:

```sh
cloudflared tunnel --no-autoupdate run novahost >> ~/novahost/novahost/data/logs/tunnel.log 2>&1 &
```

### ⚠️ قيد مهم في الشهادة المجانية

شهادة Universal SSL المجانية تغطي `example.com` و`*.example.com` — **مستوى واحد
فقط**.

- ✅ `my-site.example.com` — مغطّى
- ❌ `my-site.sites.example.com` — **غير مغطّى**، يحتاج Advanced Certificate
  Manager وهو **مدفوع**

ولهذا صُمّمت الروابط في هذا المشروع بمستوى واحد. لا تغيّر ذلك إلا إن كنت تدفع.

### ⚠️ قيد ثانٍ: حد الرفع ١٠٠ ميجابايت

الخطة المجانية (والمدفوعة Pro أيضاً) ترفض أي جسم طلب أكبر من **١٠٠ ميجابايت**
بخطأ 413 **قبل أن يصل إلى هاتفك**.

- الحد الافتراضي في المنصة ٦٤ ميجابايت لهذا السبب.
- **الرفع عبر الشبكة المحلية لا يتأثر بهذا القيد إطلاقاً.** لو كان لديك موقع
  كبير، ارفعه من اللابتوب على `http://192.168.1.XX:8080`.

## دور الراوتر

**محدود جداً، وهذا مقصود:**
- يعطي الهاتف عنوان IP (احجزه ثابتاً).
- يمرّر حركة الشبكة المحلية.
- يوفّر الاتصال الصادر الذي يفتح به `cloudflared` نفقه.

**ما لا نحتاجه:** Port Forwarding، DMZ، DDNS، IP ثابت من المزوّد.

نفق كلاودفلير يفتح اتصالاً **صادراً** من الهاتف، فلا يحتاج الراوتر أن يقبل أي
اتصال وارد. هذا ليس مجرد راحة — إنه **أفضل أمنياً**: لا منفذ مفتوح يعني لا سطح
هجوم مباشر على شبكتك المنزلية. ويعمل خلف CGNAT بلا أي مشكلة.

---

## بدائل درستُها ولماذا لم أخترها

| البديل | لماذا لا |
|---|---|
| **Port Forwarding + DDNS** | لا يعمل خلف CGNAT، ويفتح منفذاً على شبكتك المنزلية، ويحتاج Let's Encrypt يدوياً |
| **Tailscale / ZeroTier** | ممتازان لكن **شبكة خاصة**: لا تستطيع مشاركة رابط مع شخص لم يثبّت التطبيق |
| **ngrok مجاني** | رابط متغيّر وحدود جلسات أضيق من trycloudflare |
| **استضافة مجانية** | لا تحل المشكلة — نحن نستضيف على أجهزتنا بالتعريف |

**Tailscale مكمّل ممتاز وليس بديلاً:** ثبّته إن أردت الوصول إلى SSH والوحة من
الآيفون بشكل خاص تماماً دون تعريض أي شيء للإنترنت. استخدم كلاودفلير لنشر
المواقع، وTailscale للإدارة.

## اختبار الوصول

**الشبكة المحلية:** من اللابتوب افتح `http://192.168.1.XX:8080`.

**الإنترنت — الاختبار الحقيقي الوحيد:**
1. خذ الآيفون.
2. **أطفئ الواي فاي تماماً.** (هذه الخطوة هي كل شيء — على الواي فاي ستصل عبر
   الشبكة المحلية وتظن أن النفق يعمل وهو متوقف.)
3. افتح الرابط العام على بيانات 5G.

**فحص من الطرفية:**
```bash
curl -I https://panel.example.com/health
scripts/tunnel.sh status
tail -f data/logs/tunnel.log
```

---

## ماذا يحدث عند انقطاع الإنترنت؟

- الشبكة المحلية **تستمر في العمل بالكامل**: اللوحة والمواقع من `192.168.1.XX`.
- النفق ينقطع، والروابط العامة تتوقف مؤقتاً.
- عند عودة الإنترنت يعيد `cloudflared` الاتصال تلقائياً بلا تدخل منك.

هذا مقصود في التصميم: المنصة لا تعتمد على الإنترنت في شيء داخلي.
