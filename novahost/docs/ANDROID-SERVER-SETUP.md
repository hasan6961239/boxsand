# ANDROID-SERVER-SETUP

**الجهاز:** Samsung Galaxy A36 5G · Android 15 · One UI 7 (أو One UI 8 بعد التحديث)
**الهدف:** سيرفر يعمل ٢٤/٧ يستضيف لوحة NOVA HOST والمواقع المرفوعة.

هذا الدليل مكتوب لشخص **لم يستخدم Termux من قبل**. كل أمر جاهز للنسخ واللصق،
وكل نافذة ستظهر لك مشروحة قبل أن تظهر.

**الترتيب في هذا الملف:**

| القسم | متى تقرأه |
|---|---|
| [QUICK START](#quick-start) | إذا كنت تعرف Termux وتريد ١٥ دقيقة فقط |
| [FULL SETUP](#full-setup) | **ابدأ من هنا إن كانت هذه أول مرة** — الخطوات ١ إلى ٢٥ |
| [TROUBLESHOOTING](#troubleshooting) | عندما لا يعمل شيء |

> ## اقرأ هذا قبل أي شيء
>
> الخطوتان **١٦** (بطارية Samsung) و**١٧** (واي فاي أثناء السكون) ليستا تحسينات
> اختيارية. بدونهما سيتوقف السيرفر خلال دقائق من إطفاء الشاشة، **ولا يوجد أي حل
> برمجي يتجاوز ذلك** — لا في هذا المشروع ولا في غيره. هذا قرار في نظام أندرويد
> نفسه، ويُغيَّر من الإعدادات فقط.

# QUICK START

النسخة المختصرة. إن تعثّرت في أي سطر، انتقل إلى [FULL SETUP](#full-setup).

```bash
# 1. في Termux (من F-Droid، وليس Google Play)
pkg update -y && pkg upgrade -y
pkg install -y git

# 2. اجلب المشروع
cd ~
git clone https://github.com/hasan6961239/boxsand.git
cd ~/boxsand/novahost

# 3. سكربت واحد: الحزم + .env + SESSION_SECRET + قاعدة البيانات + سكربت الإقلاع
bash scripts/install-termux.sh

# 4. شغّله
scripts/start.sh

# 5. تأكد أنه يعمل
curl http://127.0.0.1:8080/health
```

ثم **بيدك، من الإعدادات — لا يمكن لأي سكربت فعلها نيابة عنك:**

1. ثبّت **Termux:Boot** و**Termux:API** من نفس مصدر Termux، و**افتح Termux:Boot مرة واحدة**.
2. `الإعدادات` ← `التطبيقات` ← Termux ← `البطارية` ← **غير مقيّد**. كرّرها لـTermux:Boot وTermux:API.
3. `الإعدادات` ← `الاتصالات` ← `Wi-Fi` ← (⋮) ← **إبقاء Wi-Fi مشغّلاً أثناء السكون**.

افتح اللوحة من اللابتوب على العنوان الذي يطبعه `scripts/status.sh`.

# FULL SETUP

## الخطوة ١ — اسمح بتثبيت التطبيقات من خارج المتجر

Termux **غير متاح على Google Play** بنسخة صالحة، لذلك ستثبّته كملف APK.
أندرويد يمنع ذلك افتراضياً، فافتح الإذن أولاً:

`الإعدادات` ← `الأمان والخصوصية` ← `المزيد من إعدادات الأمان` ←
`تثبيت تطبيقات غير معروفة` ← اختر المتصفح الذي ستنزّل به (Chrome أو Samsung Internet)
← فعّل **«السماح من هذا المصدر»**.

> قد يكون الاسم في جهازك: `تثبيت تطبيقات مجهولة المصدر` أو
> `Install unknown apps` أو `Special app access` ← `Install unknown apps`.
> كلها نفس الشيء.

## الخطوة ٢ — نزّل Termux

**لا تستخدم Google Play.** النسخة الموجودة هناك متوقفة عن التحديث منذ سنوات،
وستفشل عند أول `pkg install` برسالة غامضة.

اختر **مصدراً واحداً** والتزم به:

**المصدر الأول — F-Droid (الأسهل):**
1. افتح: **https://f-droid.org**
2. نزّل تطبيق F-Droid وثبّته.
3. افتح F-Droid، ابحث عن **Termux**، ثبّته.

**المصدر الثاني — GitHub (مباشر، بلا متجر):**
1. افتح: **https://github.com/termux/termux-app/releases**
2. من أحدث إصدار، نزّل الملف الذي ينتهي بـ:
   `...+apt-android-7-github-debug_arm64-v8a.apk`
3. الجزء **`arm64-v8a`** مهم — هذه معمارية Galaxy A36. الملفات الأخرى
   (`armeabi-v7a`, `x86_64`) لن تعمل.

## الخطوة ٣ — افتح Termux لأول مرة

ستظهر شاشة سوداء ومؤشر كتابة. هذا هو كل شيء — لا توجد واجهة.

اكتب أول أمر:

```bash
pkg update -y && pkg upgrade -y
```

**ماذا يحدث الآن:**

- `pkg update` يجلب قائمة الحزم الجديدة.
- `pkg upgrade` يحدّث ما هو مثبّت.
- `-y` معناها «نعم» تلقائياً، فلن يسألك سؤال `[Y/n]` المعتاد.

**إن ظهر سؤال رغم ذلك،** وهو يحدث مع ملفات الإعدادات:

```
Configuration file '/data/data/com.termux/files/usr/etc/motd'
 ==> What would you like to do about it ?
   Y or I  : install the package maintainer's version
   N or O  : keep your currently-installed version
   D       : show the differences
*** motd (Y/I/N/O/D/Z) [default=N] ?
```

**اضغط Enter فقط.** الخيار الافتراضي `N` (أبقِ نسختك) هو الصحيح هنا، ولن يؤثر
على المشروع إطلاقاً.

**إن ظهر خطأ في التنزيل** (`Unable to connect` أو `Could not resolve host`):

```bash
termux-change-repo
```

اختر `Main repository` ← ثم مرآة قريبة، ثم أعد `pkg update -y`.

## الخطوة ٤ — ثبّت Termux:Boot

هذا ما يجعل السيرفر يعود وحده بعد إعادة تشغيل الهاتف.

**من نفس مصدر Termux:**
- F-Droid: ابحث عن **Termux:Boot**
  (أو: https://f-droid.org/packages/com.termux.boot/)
- GitHub: https://github.com/termux/termux-boot/releases

> **لماذا نفس المصدر إجبارياً؟** أندرويد يرفض تثبيت تطبيق إضافي موقّع بمفتاح
> توقيع مختلف عن التطبيق الأساسي. إن ثبّت Termux من F-Droid وTermux:Boot من
> GitHub ستحصل على رسالة فشل غامضة مثل `App not installed`. المشكلة ليست في
> جهازك — هي هذه.

**ثم — وهذه أهم ضغطة في الدليل كله:**

**افتح تطبيق Termux:Boot مرة واحدة.**

ستظهر شاشة شبه فارغة، بلا أزرار. هذا طبيعي وصحيح. أغلقها.

**قبل هذه الضغطة لن يعمل أي سكربت إقلاع مهما كان صحيحاً.** التطبيق يبقى معطّلاً
في أندرويد حتى يُفتح يدوياً أول مرة.

## الخطوة ٥ — ثبّت Termux:API

نحتاجه لقراءة **نسبة البطارية ودرجة الحرارة** في صفحة Server داخل اللوحة.
بدونه تظهر القيمتان **«غير متاح»** — والمنصة لن تخترع رقماً مكانهما.

1. ثبّت تطبيق **Termux:API** من نفس المصدر.
2. ثم في Termux:

```bash
pkg install -y termux-api
```

> انتبه للفرق: **تطبيق** Termux:API (من F-Droid) و**حزمة** `termux-api`
> (من `pkg`). تحتاج الاثنين معاً — أحدهما بلا الآخر لا يفيد.

**تحقّق:**

```bash
termux-battery-status
```

يجب أن يطبع JSON فيه `percentage`. قد يظهر طلب إذن أول مرة — **اقبله**.
إن بقي الأمر معلّقاً بلا ناتج، فالتطبيق غير مثبّت أو لم يُمنح الإذن.

## الخطوة ٦ — أذونات التخزين

المشروع نفسها لن توضع هناك** — السبب في [الخطوة ١٠](#الخطوة-١٠--أين-تُخزَّن-البيانات،-ولماذا-ليس-sdcard).

## الخطوة ٧ — ثبّت git واجلب المشروع

```bash
pkg install -y git
```

### أي طريقة نقل أختار؟

| الطريقة | تحتاج | الصعوبة | الحكم |
|---|---|---|---|
| **Git clone** | إنترنت فقط | ★☆☆ | ✅ **الأفضل لك** |
| SCP | إعداد SSH أولاً + معرفة IP | ★★☆ | جيدة للتحديثات لاحقاً |
| SFTP | برنامج مثل WinSCP + SSH | ★★☆ | مريحة بصرياً، إعدادها أطول |
| ADB push | كبل + USB debugging + adb على ويندوز | ★★★ | لا داعي لها هنا |

**لماذا Git؟** لا تحتاج كبلاً، ولا أن يكون الهاتف واللابتوب على نفس الشبكة، ولا
إعداد SSH مسبقاً. والأهم: تحديث المشروع لاحقاً يصبح أمراً واحداً (`git pull`)
بدل إعادة نقل كل الملفات.

**المشكلة الوحيدة في SCP/SFTP/ADB:** كلها تحتاج SSH أو USB يعمل **قبل** أن
يعمل أي شيء آخر — أي أنك تحلّ مشكلتين في وقت واحد. Git يحلّ واحدة.

### اجلب المشروع

```bash
cd ~
git clone https://github.com/hasan6961239/boxsand.git
cd ~/boxsand/novahost
pwd
```

آخر أمر يطبع:

```
/data/data/com.termux/files/home/boxsand/novahost
```

**هذا مسار المشروع.** سنسميه `$NOVA` في بقية الدليل. للعودة إليه في أي وقت:

```bash
cd ~/boxsand/novahost
```

> **لتحديث المشروع لاحقاً:**
> ```bash
> cd ~/boxsand/novahost && git pull && scripts/restart.sh
> ```

## الخطوة ٨ — ثبّت Node.js وبقية الأدوات

```bash
pkg install -y nodejs-lts openssh termux-services curl
node -v
```

**المتوقع:** `v24.x.x` أو أعلى.

| الأداة | لماذا |
|---|---|
| `nodejs-lts` | تشغيل السيرفر — النسخة الحالية في Termux هي **24.18.0** |
| `openssh` | إدارة الهاتف من اللابتوب بلا لمسه |
| `termux-services` | تشغيل السيرفر كخدمة حقيقية ([الخطوة ١٩](#الخطوة-١٩--اجعله-خدمة-حقيقية)) |
| `curl` | اختبار السيرفر من الطرفية |

> **لماذا `nodejs-lts` وليس `nodejs`؟** حزمة `nodejs` تتبع أحدث إصدار (26.x
> حالياً) وتتغير كثيراً. `nodejs-lts` مخصصة للأجهزة التي يُفترض أن تبقى تعمل
> أسابيع دون لمسها — وهذا بالضبط وضعنا.
>
> **الحد الأدنى الفعلي: Node 22.13.** وحدة `node:sqlite` المدمجة أُضيفت في
> 22.5 لكنها ظلّت تحتاج راية `--experimental-sqlite` حتى 22.13. أي نسخة بينهما
> ستبدو صالحة ثم تفشل عند أول استعلام.

### ⚠️ لن تحتاج `npm install` — أبداً

هذا المشروع مصمَّم بلا أي اعتماديات وقت التشغيل. لا `node_modules`، ولا
`node-gyp`، ولا بناء يستغرق عشرين دقيقة على معالج هاتف ثم يفشل في آخر سطر.

**إن رأيت نفسك تكتب `npm install` على الهاتف، فأنت تتبع دليلاً آخر.**

للتأكد بنفسك:

```bash
grep -A2 '"dependencies"' ~/boxsand/novahost/package.json
```

## الخطوة ١٠ — أين تُخزَّن البيانات، ولماذا ليس /sdcard

**كل شيء داخل مجلد المشروع، على التخزين الداخلي لـTermux:**

```
~/boxsand/novahost/
├── backend/                  الكود
├── frontend/                 الواجهة
├── scripts/                  أوامر التشغيل والإدارة
├── .env                      ← إعداداتك وأسرارك (خارج Git)
└── data/                     ← كل ما يتغيّر أثناء العمل
    ├── novahost.db           قاعدة البيانات SQLite
    ├── novahost.db-wal       سجل الكتابة المسبقة
    ├── logs/                 السجلات
    │   ├── app-YYYY-MM-DD.log
    │   ├── server.log
    │   └── stability.csv     ← تسجيل اختبار الاستقرار
    ├── run/                  ملفات pid
    └── storage/
        ├── sites/            ملفات المواقع المرفوعة
        ├── backups/          النسخ الاحتياطية
        └── tmp/              رفع مؤقت
```

### لماذا لا نضع البيانات في `/sdcard` أو `~/storage`؟

**ليس تفضيلاً — هذه أعطال حقيقية ستقع:**

| السبب | ما الذي يحدث فعلياً |
|---|---|
| **قفل الملفات** | `/sdcard` يُركّب عبر FUSE، ولا يدعم قفل POSIX الذي يعتمد عليه SQLite في وضع WAL. النتيجة: `SQLITE_BUSY` عشوائي، وفي أسوأ الحالات **تلف قاعدة البيانات**. |
| **الصلاحيات** | لا يحفظ بت التنفيذ. السكربتات تتوقف بـ`Permission denied` حتى بعد `chmod +x`. |
| **الروابط الرمزية** | غير مدعومة. |
| **الأداء** | كل عملية تمرّ عبر طبقة FUSE — أبطأ بوضوح في القراءة والكتابة الصغيرة المتكررة، وهي نمط عمل SQLite. |
| **الحذف** | إلغاء تثبيت التطبيق أو تنظيف التخزين قد يمسح المجلد بلا سؤال. |

**الاستثناء الوحيد:** نسخ **نسخة احتياطية جاهزة** إلى مجلد التنزيلات لتنقلها،
عبر `scripts/backup.sh --to-downloads`. ملف ZIP واحد يُكتب مرة ويُقرأ مرة — لا
قفل ولا كتابة متزامنة.

> **بطاقة SD الخارجية:** نفس المشاكل، أسوأ. لا تضع `data/` عليها.

## الخطوة ١١ — الإعداد التلقائي

سكربت واحد يقوم بكل ما تبقّى من الإعداد التقني:

```bash
cd ~/boxsand/novahost
bash scripts/install-termux.sh
```

**ماذا يفعل بالضبط:**

1. يثبّت الحزم (وقد ثبّتها، فلن يعيد شيئاً)
2. ينسخ `.env.example` ← `.env`
3. **يولّد `SESSION_SECRET` قوياً** — ٤٨ بايت عشوائياً من مولّد النظام
4. يضبط `NODE_ENV=production`
5. ينشئ مجلدات `data/`
6. يشغّل migrations وينشئ قاعدة البيانات
7. يكتب سكربت الإقلاع في `~/.termux/boot/novahost`

السكربت **آمن لإعادة التشغيل**: إن كان `.env` موجوداً لن يلمسه، وإن كانت قاعدة
البيانات موجودة لن يمسحها.

### إن أردت فعلها يدوياً بدل السكربت

```bash
cd ~/boxsand/novahost

# 1. ملف الإعداد
cp .env.example .env

# 2. مفتاح الجلسات — لا تخترعه بنفسك
SECRET=$(node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))")
sed -i "s|^SESSION_SECRET=.*|SESSION_SECRET=$SECRET|" .env
sed -i "s|^NODE_ENV=.*|NODE_ENV=production|" .env

# 3. قاعدة البيانات
node backend/src/cli.js migrate
```

> ### لماذا لا تكتب كلمة سر من عندك في SESSION_SECRET؟
>
> هذا المفتاح يوقّع جلسات الدخول. من يعرفه يستطيع **تزوير جلسة مدير** بلا كلمة
> مرور. كلمة يختارها إنسان — حتى الطويلة — تأتي من فضاء احتمالات صغير جداً
> مقارنة بـ٤٨ بايت من `crypto.randomBytes`، وهو مولّد النظام العشوائي نفسه.
>
> الأمر أعلاه يولّده ويكتبه في `.env` مباشرة — **لن تراه ولن تحتاج أن تراه**.
>
> `.env` مستثنى في `.gitignore`، فلن يُرفع إلى GitHub. تأكّد:
> ```bash
> cd ~/boxsand/novahost && git status --short .env
> ```
> لا ناتج = صحيح.

**تحقّق أن الإعداد صار سليماً:**

```bash
grep -E '^(NODE_ENV|HOST|PORT|SITES_PORT)=' .env
grep -c '^SESSION_SECRET=.\{40,\}' .env
```

المتوقع:
```
NODE_ENV=production
HOST=0.0.0.0
PORT=8080
SITES_PORT=8081
1
```

الرقم `1` في آخر سطر معناه أن المفتاح مكتوب وطويل. لو كان `0` فالمفتاح فارغ —
أعد الخطوة.

> **`HOST=0.0.0.0` ضروري** ليصل اللابتوب والآيفون. لو تركته `127.0.0.1` فلن
> يصل إليه شيء غير الهاتف نفسه.

`Ctrl+C` للإيقاف.

### لماذا منفذان؟

هذا **حدّ أمني**، وليس تنظيماً:

- **8080** — اللوحة والـAPI. هنا كوكي جلستك.
- **8081** — المواقع المرفوعة فقط. لا يوجد أي مسار API عليه.

المتصفح يعتبر المنفذين **أصلين مختلفين** (different origins). وكوكي الجلسة
مضبوط بلا خاصية `Domain`، فلا يصل أبداً إلى المنفذ 8081. النتيجة: موقع مرفوع —
حتى لو كان خبيثاً — **لا يستطيع قراءة جلستك ولا استدعاء الـAPI بصلاحياتك**.

## الخطوة ١٥ — wake lock

هذا ما يمنع أندرويد من تجميد العملية عند إطفاء الشاشة.

**`scripts/start.sh` يستدعيه تلقائياً**، وكذلك سكربت الإقلاع وخدمة runit —


**للتحقق — وهذا مهم:**

اسحب شريط الإشعارات. يجب أن ترى إشعار Termux الدائم وفيه ذكر **wake lock**.

**إن لم يظهر هذا الإشعار، فالسيرفر سيتوقف عند إطفاء الشاشة** مهما فعلت في
الخطوات التالية.

## الخطوة ١٦ — ⚠️ إعدادات بطارية Samsung

**هذا أهم قسم في الدليل. تخطّيه هو السبب الأول لتوقف السيرفر.**

One UI أكثر عدوانية من أندرويد الخام في إنهاء التطبيقات التي تعمل في الخلفية.
بالإعدادات الافتراضية سيقتل Termux خلال دقائق من إطفاء الشاشة.

### أ. لكل تطبيق على حدة

`الإعدادات` ← `التطبيقات` ← **Termux** ← `البطارية` ← اختر **«غير مقيّد»**

**كرّر نفس الشيء بالضبط لـ:**
- **Termux:Boot**
- **Termux:API**

> **أسماء محتملة مختلفة حسب النسخة** — إن لم تجد الاسم أعلاه، ابحث عن أحدها:
> - `غير مقيّد` / `Unrestricted`
> - `غير مقيّد` تحت عنوان `استخدام البطارية` / `Battery usage`
> - في بعض النسخ: `التطبيقات` ← Termux ← `البطارية` ← `السماح بنشاط الخلفية`
> - أو: `تحسين البطارية` / `Battery optimization` ← اختر Termux ← **«عدم التحسين»** (Don't optimize)
>
> الهدف واحد مهما اختلف الاسم: **أخبر أندرويد ألا يوقف هذا التطبيق.**

### ب. الإعداد العام

`الإعدادات` ← `العناية بالجهاز` ← `البطارية`

ثم ابحث عن **«حدود الاستخدام في الخلفية»** (Background usage limits):

- تأكد أن **Termux ليس** في قائمة **«التطبيقات النائمة»** (Sleeping apps)
- تأكد أنه **ليس** في **«التطبيقات النائمة بعمق»** (Deep sleeping apps)
- **أطفئ** خيار **«إيقاف التطبيقات غير المستخدمة»** (Put unused apps to sleep)

> **في One UI 8 / Android 16** قد يكون المسار:
> `الإعدادات` ← `البطارية` ← `حدود الاستخدام في الخلفية`
> — أي أن `العناية بالجهاز` اختفت من المنتصف. نفس الخيارات.
>
> وقد يظهر الخيار باسم **«إيقاف نشاط التطبيق إن لم يُستخدم»**
> (Pause app activity if unused) داخل صفحة التطبيق نفسه — **أطفئه**.

### ج. إن وُجد «التشغيل التلقائي»

بعض نسخ One UI (خاصة في بعض الدول) فيها:

`الإعدادات` ← `التطبيقات` ← (⋮) ← `تشغيل تلقائي` / `Auto start`

إن وجدته، **فعّله لـTermux وTermux:Boot**. إن لم تجده فجهازك لا يملكه —
لا مشكلة، فـTermux:Boot يغطي هذا الدور.

### د. توفير الطاقة

`الإعدادات` ← `البطارية` ← تأكد أن **«توفير الطاقة»** (Power saving)
**مطفأ**. عند تفعيله يقيّد أندرويد الشبكة والمعالجة في الخلفية مهما ضبطت
الإعدادات السابقة.

## الخطوة ١٧ — ⚠️ إعدادات الواي فاي

`الإعدادات` ← `الاتصالات` ← `Wi-Fi` ← اضغط (⋮) ← `إعدادات متقدمة`:

- فعّل **«إبقاء Wi-Fi مشغّلاً أثناء السكون»**
  (Keep Wi-Fi on during sleep)
- أطفئ **«التبديل إلى بيانات الجوال»** / **«التبديل الذكي للشبكة»**
  (Switch to mobile data / Smart network switch / Adaptive Wi-Fi)

> **لماذا الثاني؟** إن ضعف الواي فاي لحظة، سينقل الهاتف نفسه إلى بيانات الجوال.
> عندها يتغيّر عنوان الهاتف المحلي ويصبح غير قابل للوصول من اللابتوب — بينما
> السيرفر يعمل تماماً. ستقضي وقتاً تبحث عن عطل غير موجود.

> **أسماء محتملة:** في بعض النسخ الخيار الأول غير موجود لأن النظام يبقيه مشغّلاً
> دائماً افتراضياً. إن لم تجده، تابع — الخطوة ١٦ هي الحاسمة.

## الخطوة ١٩ — اجعله خدمة حقيقية

حتى الآن السيرفر يعمل تحت `scripts/start.sh`، وهو مشرف حقيقي (يعيد التشغيل بعد
أي انهيار مع تأخير تصاعدي) — لكنك طلبت خدمة نظامية بأوامر `sv`. هذه متاحة:

```bash
cd ~/boxsand/novahost
bash scripts/service-install.sh
```

**بعدها تدير السيرفر هكذا:**

| ماذا تريد | الأمر |
|---|---|
| تشغيل | `sv up novahost` |
| إيقاف | `sv down novahost` |
| إعادة تشغيل | `sv restart novahost` |
| الحالة ومدة التشغيل | `sv status novahost` |
| السجلات | `tail -f ~/boxsand/novahost/data/logs/sv/current` |

**المتوقع من `sv status novahost`:**

```
run: novahost: (pid 12345) 3721s
```

الرقم الأخير هو عدد الثواني منذ آخر تشغيل. **إن كان يعود إلى رقم صغير كلما
نظرت، فالسيرفر ينهار ويُعاد تشغيله** — راجع السجلات.

> ### مشرف واحد فقط
>
> `scripts/start.sh` وrunit كلاهما يشغّل السيرفر. **لا تشغّل الاثنين** — الثاني
> سيموت فوراً بـ`Port 8080 is already in use`.
>
> `service-install.sh` يوقف المشرف الآخر تلقائياً قبل أن يبدأ، وسكربت الإقلاع
> يكتشف أيهما مثبّت ويشغّله وحده. فإن استخدمت هذه الخطوة، **انسَ
> `scripts/start.sh` تماماً** واستخدم `sv` فقط.
>
> **للتراجع والعودة إلى المشرف المدمج:**
> ```bash
> bash scripts/service-install.sh --remove
> scripts/start.sh
> ```

**إن قال لك `sv: command not found` أو `unable to connect`:**

```bash
pkg install -y termux-services
```

ثم **أغلق Termux تماماً** (اسحبه من قائمة التطبيقات الأخيرة، لا تكتفِ بالخروج)
وافتحه من جديد. `termux-services` يبدأ من ملف يُقرأ عند فتح الجلسة فقط.

## الخطوة ٢١ — الوصول من اللابتوب

### المتصفح

على HP Victus افتح:

```
http://PHONE-IP:8080
```

مثال: `http://192.168.1.14:8080`

**يجب أن تظهر لوحة NOVA HOST.** إن لم تظهر، اذهب إلى
[لا أصل من اللابتوب](#لا-أصل-إلى-اللوحة-من-اللابتوب).

### ثبّت عنوان الهاتف من الراوتر (DHCP Reservation)

بدون هذا سيتغيّر عنوان الهاتف عند إعادة التشغيل أو بعد انقطاع، وتتعطل روابطك
المحفوظة.

**١. اعرف MAC address للهاتف:**

```bash
cat /sys/class/net/wlan0/address
```

إن لم ينجح (بعض أجهزة أندرويد تحجبه):
`الإعدادات` ← `حول الهاتف` ← `الحالة` ← **«عنوان MAC للواي فاي»**

> ### ⚠️ مهم جداً في أندرويد الحديث
>
> أندرويد يستخدم **MAC عشوائياً لكل شبكة** افتراضياً، ويغيّره أحياناً. الحجز في
> الراوتر لن يثبت معه.
>
> **الحل:** `الإعدادات` ← `الاتصالات` ← `Wi-Fi` ← اضغط ⚙️ بجوار شبكتك ←
> `عرض المزيد` ← **«نوع عنوان MAC»** ← اختر **«MAC الهاتف»** (Phone MAC).
>
> ثم أعد قراءة العنوان — **سيكون مختلفاً عن السابق**. استخدم الجديد.

**٢. افتح صفحة الراوتر:**

في متصفح اللابتوب اكتب `192.168.1.1` (أو `192.168.8.1` أو `192.168.0.1` —
اقرأ الملصق خلف الراوتر، وفيه اسم المستخدم وكلمة المرور غالباً).

**٣. ابحث عن الخيار.** الاسم يختلف بين الشركات:

- `DHCP Reservation`
- `Static Lease` / `Static DHCP`
- `Address Reservation`
- `Bind IP to MAC`

غالباً تحت قسم `LAN` أو `DHCP Server` أو `Advanced`.

**٤. أضف عنصراً** يربط MAC الهاتف بالعنوان الذي تريده (مثلاً `192.168.1.14`).

**٥. أعد تشغيل واي فاي الهاتف** وتأكد أنه أخذ العنوان نفسه.

### ⛔ ما الذي لا تفعله في الراوتر

| لا تفعل | لماذا |
|---|---|
| **Port Forwarding** لـ8080/8081 | يفتح لوحة التحكم على الإنترنت كله بلا HTTPS. أي شخص يمسح المنافذ سيجدها. |
| **DMZ** للهاتف | أسوأ: يفتح **كل** منافذ الهاتف للإنترنت. |
| **UPnP** | قد يفتح منافذ دون علمك. |

**لا تحتاج أياً منها.** نفق Cloudflare ([الخطوة ٢٣](#الخطوة-٢٣--نفق-سريع-trycloudflare))
يخرج **من** الهاتف **إلى** Cloudflare، فلا يحتاج منفذاً وارداً مفتوحاً ولا عنوان
IP ثابتاً من مزوّد الإنترنت — ويعطيك HTTPS مجاناً.

### SSH — لإدارة الهاتف من اللابتوب بلا لمسه

**على الهاتف، مرة واحدة:**

```bash
passwd          # اختر كلمة مرور لحساب Termux
whoami          # اكتب الناتج، مثل u0_a234 — هذا اسم المستخدم
sshd            # شغّل خادم SSH
```

**من ويندوز (PowerShell):**

```powershell
ssh -p 8022 u0_a234@192.168.1.14
```

> **منفذ SSH في Termux هو 8022 وليس 22.** المنافذ تحت 1024 تحتاج صلاحيات
> جذر لا يملكها تطبيق عادي على أندرويد.

**مفاتيح بدل كلمة المرور (أفضل وأسرع):**

```powershell
ssh-keygen -t ed25519
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh -p 8022 u0_a234@192.168.1.14 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

**لتشغيل sshd تلقائياً:**

```bash
sv-enable sshd
```

## الخطوة ٢٢ — ✅ الاختبار الأهم: الدورة الكاملة من اللابتوب

### جهّز ملف اختبار على اللابتوب

في PowerShell:


> الموقع الحي حتى تضغط Publish. هذا ما يجعل التحرير آمناً على موقع يعمل.

**إن فشل أي سطر:** اذهب إلى [TROUBLESHOOTING](#troubleshooting) قبل المتابعة.

## الخطوة ٢٣ — نفق سريع (TryCloudflare)

الآن فقط، بعد نجاح كل ما سبق.

**رابط عام مؤقت، بلا حساب وبلا نطاق وبلا بطاقة بنكية:**

```bash
cd ~/boxsand/novahost
scripts/tunnel.sh quick
```

**المتوقع بعد ثوانٍ:**

```
ok  public URL: https://random-words-here.trycloudflare.com
```

**هذا الرابط يعمل من أي مكان في العالم فوراً، وبـHTTPS.**

### ماذا يحدث تقنياً

```
Samsung A36  ──(اتصال صادر)──>  شبكة Cloudflare  <──(HTTPS)──  الإنترنت
```

النفق يبدأ **من** الهاتف **إلى** Cloudflare. لا منفذ وارد مفتوح على الراوتر،
ولا حاجة لعنوان IP ثابت من مزوّد الإنترنت.

### قيود يجب أن تعرفها

| القيد | التفصيل |
|---|---|
| **الرابط عشوائي** | يتغيّر كلياً عند كل إعادة تشغيل للنفق |
| **غير مخصص للإنتاج** | Cloudflare توثّق ذلك صراحة — بلا ضمان استمرارية |
| **اللوحة فقط** | المنفذ 8080 وحده. المواقع تُفتح عبر مسار `/s/<slug>/` |
| **حد ١٠٠ ميجابايت** | للرفع، على الخطة المجانية |

### ✅ اختبار iPhone عبر بيانات الجوال

**هذا يثبت أن الوصول من خارج المنزل يعمل فعلاً.**

**أولاً — أطفئ الواي فاي على الآيفون تماماً:**

## الخطوة ٢٤ — نفق دائم + نطاقك الخاص

انتقل إلى هذه الخطوة **فقط بعد نجاح الخطوة ٢٣**.

### ما الذي تحتاجه فعلاً

| العنصر | التكلفة |
|---|---|
| حساب Cloudflare | **مجاني** |
| نفق Cloudflare Tunnel | **مجاني، بلا حد للنطاق الترددي** |
| شهادة HTTPS | **مجانية** (Universal SSL) |
| **اسم نطاق** | **مدفوع — ١٠ إلى ١٥ دولاراً سنوياً** |

**هذا البند الوحيد غير المجاني في المشروع كله.** لا توجد طريقة مجانية للحصول
على نطاق يعمل مع Cloudflare بشكل موثوق — نطاقات `.tk` و`.ml` المجانية سُحبت
ومُنعت. إن لم ترغب في الدفع، **ابقَ على TryCloudflare**؛ كل شيء آخر يعمل.

### أ. أنشئ حساباً وأضف النطاق

1. سجّل في **https://dash.cloudflare.com/sign-up** (مجاني)
2. اشترِ نطاقاً — من Cloudflare Registrar نفسها (بسعر التكلفة) أو Namecheap أو غيرها
3. في لوحة Cloudflare: **Add a site** ← اكتب نطاقك ← اختر خطة **Free**
4. Cloudflare ستعطيك **خادمَي أسماء** (nameservers) مثل:
   ```
   xxx.ns.cloudflare.com
   yyy.ns.cloudflare.com
   ```
5. اذهب إلى الموقع الذي اشتريت منه النطاق وغيّر nameservers إلى هذين
6. **انتظر** — قد يستغرق الانتشار من دقائق إلى ٢٤ ساعة. لوحة Cloudflare ستقول
   `Active` عندما يجهز.

### ب. أنشئ النفق (على الهاتف)

```bash
cloudflared tunnel login
```

سيطبع رابطاً. **افتحه في متصفح** (على الهاتف أو انسخه إلى اللابتوب)، سجّل
الدخول، واختر نطاقك ← `Authorize`.

ينزّل ذلك `~/.cloudflared/cert.pem`.

```bash
cloudflared tunnel create novahost
```

**المتوقع:**

```
Created tunnel novahost with id 6ff42ae2-765d-4d07-8c5b-xxxxxxxxxxxx
```

**انسخ هذا المعرّف (UUID)** — ستحتاجه في ملف الإعداد.

```bash
ls ~/.cloudflared/
```
يجب أن ترى `cert.pem` و`<UUID>.json`.

> ### 🔒 هذان الملفان أسرار
>
> من يملك `<UUID>.json` يستطيع تقديم محتوى على نطاقك. **لا يدخلان Git أبداً** —
> `.gitignore` في المشروع يستثني `.cloudflared/` مسبقاً، ولا يدخلان النسخ
> الاحتياطية.

### ج. ملف الإعداد

في المشروع ملف جاهز:

```bash
mkdir -p ~/.cloudflared
cp ~/boxsand/novahost/config/cloudflared/config.example.yml ~/.cloudflared/config.yml
nano ~/.cloudflared/config.yml
```

**غيّر ثلاثة أشياء فقط:**
1. `<TUNNEL-NAME>` ← `novahost`
2. `<TUNNEL-UUID>` ← المعرّف الذي نسخته
3. كل `example.com` ← نطاقك

**في nano:** `Ctrl+O` ثم `Enter` للحفظ، `Ctrl+X` للخروج.

الملف يبدو هكذا بعد التعديل:

```yaml
tunnel: novahost
credentials-file: /data/data/com.termux/files/home/.cloudflared/6ff42ae2-765d-4d07-8c5b-xxxxxxxxxxxx.json
no-autoupdate: true
loglevel: info

ingress:
  - hostname: panel.mysite.com
    service: http://localhost:8080

  - hostname: "*.mysite.com"
    service: http://localhost:8081

  - service: http_status:404
```

> ### ⚠️ ترتيب القواعد ليس تفصيلاً
>
> تُقرأ من الأعلى للأسفل، **وأول تطابق يفوز**. قاعدة `panel` **يجب** أن تسبق
> `*`، لأن `*.mysite.com` تطابق `panel.mysite.com` أيضاً. لو عكست الترتيب
> ستذهب لوحة التحكم إلى منفذ المواقع (8081)، حيث لا يوجد API — وستحصل على
> صفحة بيضاء أو 404 بلا سبب واضح.
>
> والسطر الأخير `http_status:404` **إجباري**: cloudflared يرفض البدء بدون
> قاعدة ختامية بلا hostname.

### د. سجلات DNS

```bash
cloudflared tunnel route dns novahost panel.mysite.com
cloudflared tunnel route dns novahost "*.mysite.com"
```

كل أمر ينشئ سجل `CNAME` مُوجَّهاً (proxied) إلى النفق.

**تحقّق في لوحة Cloudflare** ← `DNS` ← يجب أن ترى سجلّين والسحابة **برتقالية**
(Proxied). لو كانت رمادية فالنفق لن يعمل ولا HTTPS.

### هـ. ⚠️ لماذا `project1.mysite.com` وليس `project1.sites.mysite.com`

**شهادة Universal SSL المجانية تغطي مستوى واحداً فقط:**

| النطاق | مغطّى مجاناً؟ |
|---|---|
| `mysite.com` | ✅ |
| `panel.mysite.com` | ✅ |
| `project1.mysite.com` | ✅ |
| `project1.sites.mysite.com` | ❌ **يحتاج Advanced Certificate Manager المدفوع** |

لذلك تصميم المنصة يضع كل مشروع على **مستوى واحد**: `<slug>.mysite.com`.
هذا ليس تفضيلاً جمالياً — هو ما يجعل HTTPS مجانياً لكل مشروع.

### و. اربط المشروع بالنطاق

في `.env` على الهاتف:

```bash
cd ~/boxsand/novahost
nano .env
```

اضبط:

```

PANEL_HOST=panel.mysite.com
SITES_DOMAIN=mysite.com
TRUST_PROXY=true
```

> **`TRUST_PROXY=true` هنا فقط.** خلف نفق Cloudflare، عنوان الزائر الحقيقي يصل
> في ترويسة `X-Forwarded-For` ويجب الوثوق بها لتعمل حدود المعدّل بشكل صحيح.
> في الشبكة المحلية تبقى `false`، لأن لا شيء يقف أمام السيرفر هناك وأي جهاز على
> الواي فاي يستطيع تزوير الترويسة ليحصل على حصة جديدة.

ثم:

```bash

```

# TROUBLESHOOTING

## السيرفر توقف بعد إطفاء الشاشة

**السبب في ٩٥٪ من الحالات: إعدادات بطارية Samsung.**

```bash
# هل ما زال يعمل؟
cd ~/boxsand/novahost && scripts/status.sh
```

**افحص بالترتيب:**

1. **إشعار wake lock** — اسحب شريط الإشعارات. لا يوجد إشعار Termux فيه
   `wake lock`؟ → `termux-wake-lock` ثم أعد التشغيل.
2. **البطارية** — [الخطوة ١٦](#الخطوة-١٦---إعدادات-بطارية-samsung) كاملة،
   ولكل التطبيقات الثلاثة وليس Termux وحده.
3. **«إيقاف التطبيقات غير المستخدمة»** — يجب أن يكون **مطفأ**.
4. **توفير الطاقة** — يجب أن يكون **مطفأ**.

**تحقّق أنك فعلاً ضبطتها:** `الإعدادات` ← `التطبيقات` ← Termux ← `البطارية` —
يجب أن تقرأ **«غير مقيّد»** وليس «محسّن» أو «مقيّد».

## Termux:Boot لا يشتغل

```bash
ls -l ~/.termux/boot/novahost
```

**الأسباب الثلاثة، بالترتيب:**

1. **لم تفتح تطبيق Termux:Boot ولو مرة واحدة** ← هذا هو السبب في أغلب الحالات.
   افتحه الآن وأعد تشغيل الهاتف.
2. **البطارية تمنعه** ← Termux:Boot **نفسه** يحتاج «غير مقيّد»، ليس Termux فقط.
3. **الملف غير قابل للتنفيذ** ← `chmod +x ~/.termux/boot/novahost`

**هل حاول العمل أصلاً؟**

```bash
cat ~/.termux/boot/novahost.log 2>/dev/null
```

إن وجدت فيه `no start.sh found` فالمسار خاطئ — عدّل السكربت أو انسخه من جديد:

```bash
cp ~/boxsand/novahost/scripts/boot.sh ~/.termux/boot/novahost
chmod +x ~/.termux/boot/novahost
```

## السيرفر لم يعد بعد إعادة تشغيل الهاتف

```bash
# 1. شغّله يدوياً للتأكد أن المشكلة في الإقلاع وليس في السيرفر
cd ~/boxsand/novahost && scripts/start.sh

# 2. إن نجح، فالمشكلة في Termux:Boot ← القسم السابق
```

**بياناتك آمنة في كل الحالات:** كل شيء في `data/` على تخزين Termux الداخلي، ولا
يتأثر بإعادة التشغيل.

## لا أصل إلى اللوحة من اللابتوب

**افحص بالترتيب — لا تقفز:**

```bash
# 1. هل السيرفر يعمل على الهاتف أصلاً؟
curl http://127.0.0.1:8080/health
```

**إن فشل هذا** فالمشكلة في السيرفر، لا في الشبكة → `scripts/logs.sh server -n 50`

**إن نجح**، فالمشكلة في الشبكة:

| افحص | الأمر / الإجراء |
|---|---|
| `HOST=0.0.0.0` وليس `127.0.0.1` | `grep '^HOST=' .env` |
| العنوان صحيح | `scripts/status.sh` — قسم `reachable at` |
| الجهازان على **نفس** الشبكة | ليس أحدهما على شبكة الضيوف أو 5GHz منفصلة |
| الهاتف لم ينتقل لبيانات الجوال | أطفئ «التبديل إلى بيانات الجوال» |
| جدار حماية ويندوز | جرّب من الآيفون أيضاً — إن عمل، فالمشكلة في ويندوز |
| **AP Isolation** في الراوتر | يمنع الأجهزة من رؤية بعضها. أطفئه من إعدادات الواي فاي في الراوتر |

**اختبار سريع من اللابتوب:**

```powershell
Test-NetConnection -ComputerName 192.168.1.14 -Port 8080
```

`TcpTestSucceeded : True` = الشبكة سليمة والمشكلة في المتصفح.

```bash
scripts/tunnel.sh status
tail -n 40 ~/boxsand/novahost/data/logs/tunnel.log
```

| الرسالة | المعنى | الحل |
|---|---|---|
| `failed to connect` | لا إنترنت على الهاتف | افحص الاتصال |
| `credentials file not found` | مسار خاطئ في `config.yml` | `ls ~/.cloudflared/` وصحّح المسار |
| `ingress rules... invalid` | لا توجد قاعدة ختامية | أضف `- service: http_status:404` في آخر الملف |
| اللوحة تعطي 404 | ترتيب القواعد معكوس | `panel` **قبل** `*` |
| `ERR_TOO_MANY_REDIRECTS` | وضع SSL في Cloudflare | لوحة Cloudflare ← `SSL/TLS` ← **Full** |
| رفع ZIP يفشل عند ~١٠٠ ميجا | حد الخطة المجانية | ارفع ملفاً أصغر، أو استخدم الشبكة المحلية للملفات الكبيرة |

## `Port 8080 is already in use`

نسخة تعمل بالفعل — غالباً شغّلت المشرفين معاً:

```bash
cd ~/boxsand/novahost
scripts/stop.sh

scripts/start.sh      # أو: sv up novahost
```

## البطارية أو الحرارة تقول «غير متاح»

**هذا ليس عطلاً بالضرورة.**

1. هل **تطبيق** Termux:API مثبّت؟ (غير حزمة `termux-api`)
2. جرّب: `termux-battery-status` — لا ناتج = التطبيق ناقص أو الإذن مرفوض
3. إن عملت البطارية وبقيت الحرارة «غير متاح»، فجهازك لا يعرض مناطق الحرارة
   لتطبيق عادي. **لا يوجد حل، والمنصة لن تخترع رقماً.**

## الشبكة تقول «غير متاح»

**هذا طبيعي ومتوقع.** أندرويد 10 فما فوق يحجب `/proc/net/dev` عن التطبيقات
العادية. لا حل، والقيمة تبقى «غير متاح» بدل رقم مخترع.

## التخزين يمتلئ

```bash
node backend/src/cli.js cleanup
```

أو من اللوحة: **Server** ← **Run cleanup**. يحذف السجلات القديمة والجلسات
المنتهية والنشرات القديمة (مع إبقاء المنشور حالياً وعدداً من السابقين).
