# تقرير المراجعة — حالة المشروع الحقيقية

مراجعة للكود الموجود فعلاً في `novahost/`، وليست وصفاً لما كان يُفترض بناؤه.
كل بند هنا مصحوب بكيفية التحقق منه.

**طريقة التحقق:** ٣٦ ادعاءً في `ANALYSIS.md` فُحصت آلياً مقابل الكود المصدري،
و١٣٦ اختباراً آلياً، ودورة كاملة في متصفح حقيقي، و٢٩٧ ضغطة زر على كل عنصر
تفاعلي في الواجهة، وفحوص أمنية عدائية بمقابس خام (raw sockets).

| المجال | الحالة | كيف تحقّقتُ |

## ٢) ما الذي يعمل لكنه يحتاج تحسيناً

| البند | الحالة الآن | التحسين المقترح |
|---|---|---|
| **وضع المسار `/s/slug/`** | يعمل بحقن `<base>` | الروابط **المطلقة** (`/css/x.css`) لا يصلحها `<base>`. هناك إعادة توجيه احتياطية عبر `Referer` لكنها ليست مضمونة. **الحل الصحيح: استخدم اسم مضيف** (`slug.localhost` أو sslip.io أو نطاق حقيقي) |
| **تجاوز حد المعدل بـ XFF** | `TRUST_PROXY=false` افتراضياً الآن | عند تفعيل النفق ستضبطه `true`، وحينها كلاودفلير تكتب العنوان الحقيقي. قفل الحساب يحمي تسجيل الدخول في الحالتين |
| **`/health` بلا مصادقة** | مقصود — المشرف يحتاجه | يكشف فقط: يعمل/لا يعمل + مدة التشغيل. لا مسارات ولا أعداد |
| **«خاص» (private)** | يخفي من القوائم ومحركات البحث | **لا يمنع الوصول بالرابط** — هذا ما طلبتَه في البند ٥٣، لكن اعرفه بوضوح |
| **قياس حجم السجلات** | تقدير لا قياس | `dbstat` غير مترجَم في كل نسخ SQLite. التقدير كافٍ للعرض |
| **النطاقات المخصصة** | تحقق TXT يعمل | لا تُصدر شهادات — كلاودفلير تفعل. هذا مقصود |

## ٣) ما الذي لم يُنفَّذ (وسبب كل بند)

| الميزة | الحالة | لماذا |
|---|---|---|
| **تشغيل كود مرفوع** (Node/PHP/Python) | ❌ غير منفَّذ **عمداً** | بلا عزل حقيقي، أي موقع ترفعه يملك الهاتف. مختبَر: PHP وCGI يُقدَّمان كنص خام ولا يُنفَّذان |
| **بناء أطر العمل** (React/Vite/Next) | ❌ غير منفَّذ | نفس السبب. ابنِ على اللابتوب وارفع `dist/` |
| **CLI (`myhost deploy`)** | ⚠️ الأساس جاهز | جدول `api_keys` ودواله موجودة في `db/repo/apikeys.js` لكن **لا مسارات HTTP** بعد |
| **تكامل Git / Auto Deploy** | ❌ غير منفَّذ | المعمارية تسمح به: مصدر نشر رابع بجانب `zip`/`editor`/`rollback` |
| **مصادقة ثنائية (2FA)** | ❌ غير منفَّذ | البديل الأقوى والمجاني الآن: Cloudflare Access أمام اللوحة |
| **Analytics (زوار/نطاق ترددي)** | ❌ غير منفَّذ | طلبتَ ألا يكون أساسياً الآن |
| **نسخ احتياطي مجدول** | ❌ غير منفَّذ | يدوي عبر الزر أو `scripts/backup.sh`. الجدولة تحتاج cron لا يوجد على أندرويد |
| **مستخدمون متعددون** | ⚠️ المخطط يدعمه | `users.role` و`projects.owner_id` موجودان؛ لا واجهة إدارة مستخدمين |

**لا يوجد في المشروع:** أي `TODO`، أي `Coming Soon`، أي بيانات وهمية، أي زر
شكلي. تحقّقتُ آلياً من ذلك عبر فحص كل ملف مصدري.

## ٤) ما الذي يحتاج إعداداً يدوياً على Samsung

هذه **لا يستطيع أي سكربت تنفيذها** — تحتاج لمس الشاشة:

| # | الإجراء | إن تخطيته |
|---|---|---|
| 1 | ثبّت Termux من **F-Droid أو GitHub** (لا Play Store) | `pkg install` سيفشل |
| 2 | ثبّت **Termux:Boot** من نفس المصدر **وافتحه مرة واحدة** | لن يعمل الإقلاع التلقائي أبداً |
| 3 | ثبّت **Termux:API** | البطارية والحرارة = «غير متاح» |
| 4 | `الإعدادات ← التطبيقات ← Termux ← البطارية ← غير مقيّد` | **السيرفر يتوقف بعد دقائق من إطفاء الشاشة** |
| 5 | كرّر البند 4 لـ Termux:Boot وTermux:API | نفس النتيجة |
| 6 | `العناية بالجهاز ← البطارية ← أطفئ «إيقاف التطبيقات غير المستخدمة»` | توقف بعد أيام |
| 7 | `Wi-Fi ← متقدم ← إبقاء Wi-Fi مشغّلاً أثناء السكون` | ينقطع الوصول عند سكون الشاشة |
| 8 | `Wi-Fi ← إعدادات الشبكة ← نوع MAC ← «MAC الهاتف»` | حجز IP في الراوتر لن يثبت |
| 9 | `termux-setup-storage` واقبل الإذن | لا يمكن نسخ النسخ الاحتياطية للتنزيلات |

التفاصيل كاملة في [ANDROID-SERVER-SETUP.md](ANDROID-SERVER-SETUP.md).

## ٥) ما الذي يحتاج إعداداً في الراوتر

**واحد فقط، وهو مستحسن لا إلزامي:**

| الإجراء | لماذا |
|---|---|
| **حجز IP ثابت للهاتف** (DHCP Reservation) | حتى لا يتغيّر العنوان المحلي عند إعادة التشغيل |

**ما لا تحتاجه إطلاقاً:**
- ❌ Port Forwarding
- ❌ DMZ
- ❌ IP عام ثابت من المزوّد
- ❌ DDNS
- ❌ فتح أي منفذ

نفق كلاودفلير يفتح اتصالاً **صادراً** من الهاتف، فلا يحتاج الراوتر قبول أي
اتصال وارد. **هذا أفضل أمنياً وليس مجرد راحة**: لا منفذ مفتوح = لا سطح هجوم
مباشر على شبكتك، ويعمل خلف CGNAT.

**تحقق واحد:** إن لم يصل اللابتوب إلى الهاتف رغم أنهما على نفس الواي فاي، فقد
يكون **AP Isolation** مفعّلاً في الراوتر — أطفئه.

## ٦) ما الذي يحتاج إعداداً في Cloudflare

**للاختبار السريع: لا شيء.**
```bash
scripts/tunnel.sh quick
```
رابط عام بـHTTPS خلال ثوانٍ، بلا حساب وبلا نطاق. الرابط يتغيّر مع كل تشغيل.

**للعنوان الدائم — بالترتيب:**

| # | الإجراء | التكلفة |
|---|---|---|
| 1 | أنشئ حساب Cloudflare | مجاني |
| 2 | **اشترِ نطاقاً** أو انقل نطاقاً تملكه | **١٠–١٥ دولاراً سنوياً** ← الشيء الوحيد غير المجاني |
| 3 | غيّر nameservers إلى كلاودفلير وانتظر التفعيل | مجاني |
| 4 | `cloudflared tunnel login` من الهاتف | مجاني |
| 5 | `cloudflared tunnel create novahost` | مجاني |
| 6 | انسخ `config/cloudflared/config.example.yml` وعدّل الثلاثة placeholders | — |
| 7 | `cloudflared tunnel route dns novahost panel.example.com` | مجاني |
| 8 | `cloudflared tunnel route dns novahost '*.example.com'` | مجاني (wildcard موكَّل متاح على المجانية منذ 2022) |
| 9 | اضبط `PANEL_HOST` و`SITES_DOMAIN` و`PUBLIC_URL` و`TRUST_PROXY=true` في `.env` | — |
| 10 | `scripts/restart.sh` ثم `scripts/tunnel.sh run novahost` | — |

**قيدان مجانيان مأخوذان في التصميم:**
- الشهادة المجانية تغطي **مستوى نطاق واحداً**: `slug.example.com` ✅ /
  `slug.sites.example.com` ❌ (يحتاج ACM المدفوع)
- الرفع فوق **١٠٠ ميجابايت** مرفوض قبل وصوله للهاتف → الحد الافتراضي ٦٤، والرفع
  المحلي غير متأثر

**إجراء إضافي مجاني وقوي:** ضع **Cloudflare Access** أمام `panel.example.com`
(مجاني حتى ٥٠ مستخدماً) — طبقة تحقق قبل أن يصل أحد إلى شاشة الدخول أصلاً.

## ٧) ما الذي يمكن اختباره الآن على Windows

**كل شيء عدا العتاد.** لا تحتاج الهاتف إطلاقاً للبدء:

```powershell
cd novahost
.\scripts\dev.ps1 setup     # يجهّز .env وقاعدة البيانات — بلا npm install
.\scripts\dev.ps1 start     # http://localhost:8080
.\scripts\dev.ps1 test      # 136 اختباراً
```

| ✅ يعمل بالكامل على ويندوز | ⚠️ يحتاج الهاتف |
|---|---|
| معالج الإعداد وتسجيل الدخول | البطارية والحرارة (Termux:API) |
| إنشاء المشاريع ورفع ZIP والنشر | إصدار أندرويد واسم الجهاز |
| فتح الموقع ومعاينته | سكربتات Termux |
| مدير الملفات والمحرر | الإقلاع التلقائي |
| التراجع بين النسخ | النفق (يعمل على ويندوز أيضاً بـcloudflared) |
| النسخ الاحتياطي والاستعادة | |
| كل الإحصاءات (معالج/ذاكرة/قرص/شبكة) | |
| السجلات والإعدادات والنطاقات | |
| ١٣٦ اختباراً آلياً | |

**الفرق الوحيد في السلوك:** الإحصاءات الخاصة بأندرويد تظهر «غير متاح» على
ويندوز — وهذا هو السلوك الصحيح نفسه الذي ستراه على هاتف بلا Termux:API.

## نتائج الفحص الأمني

**المنهج:** فحص عدائي بطلبات حقيقية ومقابس خام، لا قراءة كود فقط.

| الخطورة | النتيجة | الحالة |
|---|---|---|
| CRITICAL | لا شيء | — |
| HIGH | «مشروع يقرأ ملفات مشروع آخر» | ❎ **مرفوضة — خطأ في الاختبار**: `fetch()` طبّع `..` من الرابط، فالنتيجة كانت الرابط العام الشرعي للمشروع الآخر. أُعيد الاختبار بمقبس خام: ٧/٧ محاولات محجوبة، و`safeJoin` يحجب ٧/٧ مستقلاً عن مطبّع الروابط |
| LOW | «SVG يُعرَض داخل أصل اللوحة» | ✅ **أُصلحت** — SVG صورة بحسب النوع وحاوية سكربتات في الواقع. الآن تُنزَّل ولا تُعرَض |
| LOW | «توقيت الدخول يكشف وجود الحساب» | ❎ **مرفوضة — خطأ في الاختبار**: قاس القفل لا التجزئة. القياس النظيف: ٤٠.٩ms مقابل ٤٠.٥ms (نسبة ١.٠١) |
| MEDIUM | `TRUST_PROXY=true` افتراضياً | ✅ **أُصلحت** — صار `false`، لأن الوضع الأول هو الشبكة المحلية حيث لا وسيط والترويسة قابلة للتزوير |

**ما تحقّقتُ منه ونجح:**
- لا وصول للقاعدة أو النسخ الاحتياطية عبر HTTP
- كلمة المرور غير مستخرَجة من ملف القاعدة، ورمز الجلسة مخزَّن مجزّأً فقط
- لا كلمات مرور ولا رموز جلسات ولا أسرار في السجلات
- CSRF والأصل مفروضان؛ الكوكي host-only وHttpOnly
- PHP وCGI يُقدَّمان كنص ولا يُنفَّذان
- الامتدادات المجهولة تعود `application/octet-stream` لا `text/html`
- لا `Access-Control-Allow-Origin: *`
- النسخة الاحتياطية لا تحتوي `SESSION_SECRET`

**إصلاحان إضافيان من مراجعة الواجهة:**
- زر القائمة (☰) كان ظاهراً على سطح المكتب بسبب ترتيب قواعد CSS → أُصلح بالتخصيص
- زر «إضافة نطاق» بحقل فارغ كان يصمت → صار يُظهر تنبيهاً ويركّز الحقل
