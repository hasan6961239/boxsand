# منظومة صيدليتي

منظومة إدارة صيدليات عربية بالكامل، تعمل **محلياً على جهاز الصيدلية بدون إنترنت** — مصمّمة لظروف السوق الليبي (انقطاع النت والكهرباء، اقتصاد نقدي، بيع بالآجل).

**التجربة المباشرة:** <https://claude.ai/code/artifact/825a9161-37f9-4327-9bb8-178e48fb04d0>
**صفحة البيع:** <https://claude.ai/code/artifact/8ee5a575-1bc1-45e1-9a99-2074f84767f2>

---

## التشغيل السريع

```bash
npm install      # يحتاج إنترنت مرة واحدة فقط
npm run seed     # بيانات تجريبية واقعية (١١٦ صنفاً، ٩٠ يوم مبيعات)
npm start        # ثم افتح http://localhost:3000
```

الدخول: `admin` / `1234`

على ويندوز: اضغط مرتين على `scripts\windows\تشغيل-المنظومة.bat`

---

## ما الذي يميّزها

**تتبّع الدفعات وتواريخ الصلاحية.** كل توريد يُسجَّل كدفعة مستقلة برقمها وتاريخ انتهائها وتكلفتها. البيع يخصم من **الأقرب انتهاءً أولاً** (FEFO) ويتجاهل المنتهية تماماً، فلا تُباع علبة منتهية بالخطأ. شاشة التنبيهات تعرض قيمة البضاعة المعرّضة للتلف بالدينار — وهي الميزة التي تبيع المنظومة.

**تعمل بدون إنترنت.** خادم محلي على جهاز الصيدلية. عدة أجهزة تتصل عبر شبكة المحل بدون أي خدمة خارجية.

**لا مكتبات خارجية عملياً.** التبعية الوحيدة هي `better-sqlite3`. الخادم مبني على وحدات Node المدمجة، والواجهة بدون خطوة بناء — ما يجعل التثبيت على جهاز بعيد بإنترنت ضعيف أمراً ممكناً.

## البنية

```
server/           خادم Node (بدون إطار عمل)
  db.js           مخطط SQLite
  http.js         موجّه ومخدّم ملفات
  auth.js         scrypt + جلسات + صلاحيات
  seed.js         مولّد بيانات تجريبية
  routes/         inventory · sales · purchases · parties · reports · admin
public/           الواجهة (ES modules، بدون بناء)
  js/views/       ١٢ شاشة
  js/api.js       طبقة اتصال تعمل مع الخادم أو محرّك العرض
demo/             مُجمِّع نسخة العرض في ملف HTML واحد
docs/             دليل التثبيت ودليل المستخدم
sales-kit/        خطة البيع، النصوص، التسعير، صفحة البيع
scripts/          اختبارات وأدوات تشغيل
```

### طبقة الاتصال

`public/js/api.js` تعمل مع مصدرين: الخادم الحقيقي عبر `fetch`، أو محرّك عرض داخل المتصفح
(`demo-engine.js`) ينفّذ نفس الواجهة على بيانات في الذاكرة. لهذا تعمل **نفس شيفرة الواجهة**
في المنتج وفي نسخة العرض المستقلة، بدون ازدواج.

## الأوامر

```bash
npm start                  # تشغيل الخادم (PORT=3000)
npm run seed               # بيانات تجريبية (يرفض الكتابة فوق بيانات قائمة)
npm run reset              # إعادة توليد من الصفر — يحذف كل شيء
npm run demo               # بناء نسخة العرض في ملف HTML واحد

DEMO_WHATSAPP=2189xxxxxxx npm run demo    # مع زر واتساب في نسخة العرض

./scripts/smoke-test.sh    # ٤٢ اختباراً لنقاط الـ API (يتطلب خادماً يعمل)
./scripts/check-esm.sh     # فحص صياغة ملفات الواجهة
./scripts/dev-server.sh start|stop
```

---

## الاختبارات

- **`scripts/smoke-test.sh`** — ٤٢ اختباراً تغطي المصادقة، المخزون، دورة البيع الكاملة،
  رفض الكميات غير المتوفرة، المرتجعات، التقارير، النسخ الاحتياطي، وفرض الصلاحيات على الخادم.
- **`scripts/check-esm.sh`** — يفحص صياغة كل ملفات الواجهة.
- اختبار متصفح (Playwright) يغطي الشاشات الاثنتي عشرة ودورة بيع كاملة عبر الواجهة.

## ملاحظات أمنية

المنظومة مصمَّمة للتشغيل على **شبكة محلية موثوقة داخل المحل**، لا على الإنترنت المفتوح:

- كلمات المرور مخزّنة بـ scrypt، والجلسات برموز عشوائية تنتهي بعد ٣٠ يوماً.
- الصلاحيات مفروضة على الخادم لا في الواجهة فقط.
- لا يوجد HTTPS ولا حماية CSRF — غير مطلوبَين داخل شبكة المحل، ومطلوبان قبل أي تعريض للإنترنت.
- غيّر كلمة مرور `admin` الافتراضية عند كل تركيب.
