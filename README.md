# منظومة المكتبة والقرطاسية

نظام بيع ومخزون لمحلات الكتب والقرطاسية. يعمل **بلا إنترنت بالكامل** على ويندوز،
بلا صلاحيات مدير وبلا برامج مساعدة.

نواة صغيرة بلغة C# تفتح خادماً محلياً على `127.0.0.1` وتستعمل متصفح ويندوز
نفسه كواجهة — فلا Electron ولا مئات الميجابايت. كل البيانات في ملف واحد على
جهاز المحل.

---

## بنية المشروع

```
src/Program.cs        النواة: الخادم المحلي، الترخيص، الحفظ، النسخ الاحتياطي
app/                  الواجهة — تُدمج داخل الملف التنفيذي عند البناء
  index.html
  styles.css
  js/core.js          الحالة، الحفظ، ملكية النافذة، الأدوات المشتركة
  js/inventory.js     الكتب والقرطاسية والاستيراد
  js/sales.js         نقطة البيع والفواتير والإرجاع
  js/people.js        الزبائن والديون والموردون
  js/branches.js      ربط الفروع وطلبات التحويل
  js/reports.js       التقارير والأرباح والإعدادات
  js/consign.js       الكتب على المباع
  js/count.js         الجرد الفعلي
  js/notify.js        إشعارات الهاتف (ntfy)
cloud/worker.js       صندوق بريد الفروع — يُرفع على Cloudflare Workers
tools/dev-server.js   خادم تطوير للتجربة على لينكس/ماك
tools/test.js         اختبار تراجع آلي
docs/                 دليل الزبون
build.bat             بناء الـEXE على ويندوز
```

## البناء (ويندوز)

انقر `build.bat` مرتين. لا يحتاج تنصيب أي شيء — مترجم C# موجود داخل ويندوز.

```
build.bat                 الفرع الأول  (مصراتة)
build.bat tripoli 2       فرع ثانٍ برمز ومدينة مختلفين
```

الناتج في `build\Qirtasiya-1.exe`.

## التطوير (لينكس / ماك)

```
npm install
node tools/dev-server.js      # ثم افتح http://127.0.0.1:17845/
node tools/test.js            # اختبار التراجع (32 حالة)
```

`tools/dev-server.js` يحاكي نواة `Program.cs` بنفس عقد الـAPI — للتجربة فقط،
والمنتج النهائي دائماً هو الـEXE.

لتعديل الواجهة بلا إعادة بناء على ويندوز: ضع ملفاً فارغاً باسم `dev-mode.txt`
بجانب البرنامج، فيقرأ مجلد `app` المجاور بدل الموارد المدمجة. **لا تضعه عند
الزبون** — وجوده يسمح باستبدال الواجهة.

## ما الذي تغيّر في الإصدار 2.2

مراجعة تقنية كاملة كشفت أخطاء تفقد بيانات وثغرات أمنية. هذه إصلاحاتها.

### فقدان البيانات

| المشكلة | الإصلاح |
|---|---|
| نافذتان مفتوحتان تدهسان عمل بعضهما بصمت — بيع كامل يختفي | ملكية نافذة واحدة (`/api/claim` + نبض كل 5 ثوانٍ). الثانية للعرض فقط مع شريط تحذير وزر «تحكّم من هذه النافذة» |
| ملف بيانات تالف ⇒ المنظومة تبدأ فارغة بصمت ثم تكتب فوقه | `JSON.parse` صريح، شاشة استرجاع تعرض النسخ، ومنع الحفظ كلياً حتى يختار المستخدم |
| جسم مبتور يستبدل ملفاً سليماً (الفحص كان `body[0]=='{'` فقط) | تحقق كامل من صحة JSON في النواة قبل الاستبدال + ثلاثة أجيال بدل جيل واحد |
| كل النسخ الاحتياطية على نفس القرص وفي مجلد البرنامج | «مجلد نسخ إضافي» في الإعدادات (فلاشة أو مجلد سحابي) — تُنسخ إليه كل نسخة |
| 150 نسخة يومية × 10 ميجابايت = 1.5 جيجابايت بعد سنة | 30 نسخة يومية + نسخة واحدة من كل شهر |

### الأمان

| المشكلة | الإصلاح |
|---|---|
| أي صفحة ويب يزورها صاحب المحل تستطيع مسح قاعدة بياناته أو تشغيل أداة إلغاء التثبيت | حارس ثلاثي على `/api/`: فحص `Host` (يغلق DNS rebinding)، فحص `Origin`، وترويسة `X-Qirtasiya` المخصّصة التي تُجبر المتصفح على preflight يفشل من أي أصل آخر |
| `GET /C:/Windows/win.ini` يقدّم أي ملف على القرص (`Path.Combine` يُرجع المسار المطلق كما هو) | التحقق أن المسار النهائي داخل مجلد الواجهة فعلاً، ومجلد `app` لا يُقرأ إلا في وضع التطوير |
| رمز قفل الأرباح بالنص الصريح في `store.json` ويظهر على `/api/load` | يُخزَّن مجزّأً (SHA-256) في النواة، والتحقق عبر `/api/profit-unlock` — الواجهة لا تعرف الرمز |
| تخطّي الترخيص بوضع `app\index.html` معدّل | مسارات البيانات كلها مغلقة بلا ترخيص، ومجلد `app` خلف راية تطوير |
| إرجاع ساعة ويندوز يمدّد ترخيصاً منتهياً | حفظ أحدث تاريخ رُئي ورفض أي قفزة إلى الوراء |

### حسابات وأرقام

| المشكلة | الإصلاح |
|---|---|
| استيراد CSV بأرقام عربية (`١٥`, `٠٫٥`) ⇒ أسعار وكميات **صفر** بصمت | تطبيع الأرقام العربية والفارسية والفاصلة العشرية العربية، مع تنبيه بعدد الخانات التي لم تُقرأ |
| `1,5` تصير `15` — عشرة أضعاف السعر | تمييز الفاصلة العشرية عن فاصل الآلاف |
| خانات السعر ترفض الأرقام العربية وتبقى فارغة | حقول `inputmode="decimal"` تقبلها وتحوّلها أمام المستخدم |
| خصم 500 على فاتورة 30 يسجّل ربحاً `‎−490‎` ويفسد تقارير السنة | الخصم مقصوص عند المجموع، والربح يُحسب من الخصم المطبَّق فعلاً |
| إمكانية بيع «2.5 قلم» | الكميات صحيحة إلا للوحدات التي تُباع بالكسور (متر، كيلو، لتر، جرام) |

### الأداء والتجربة

| المشكلة | الإصلاح |
|---|---|
| صفحة الفواتير بعد سنة: 21,900 صفاً و481 ألف عنصر — تجمّد النافذة 73 ثانية | مرشّح آخر 30 يوماً افتراضياً، 200 صف لكل صفحة، وزر «عرض المزيد» و«كل التواريخ». صارت 44 مللي ثانية |
| شاشة المخزون الفارغة تطلب إضافة صنف بلا زر يؤديه | زرّا «+ كتاب جديد» و«+ صنف قرطاسية» في الحالة الفارغة |
| الإشعار اليومي يرسل الربح إلى قناة ntfy عامة، والدليل يَعِد بالعكس | الربح لا يُرسل، وصار خياراً منفصلاً مطفأً افتراضياً مع تحذير صريح |

## اختبار التراجع

`tools/test.js` يغطي كل خلل من المراجعة بحالة اختبار — 32 حالة تشمل:
تطبيع الأرقام، قصّ الخصم، الكميات، أداء الفواتير مع بيانات سنة، سيناريو
النافذتين، الملف التالف، محاولة كتابة من صفحة خارجية، رمز الأرباح،
محتوى الإشعار اليومي، وسلامة الشاشات الثلاث عشرة.

```
node tools/dev-server.js &
node tools/test.js
```

## يبقى على صاحب المشروع

هذه أمور لا يمكن إصلاحها من داخل الكود:

1. **مولّد التراخيص يحمل المفتاح الخاص بالنص الصريح.** ولّد زوج مفاتيح
   جديداً، ضع المفتاح العام في `PUB_N` داخل `src/Program.cs`، وأصدر نسخة
   جديدة. أضف إلى المولّد سجلاً بمن صدر له كل ترخيص ومتى — حالياً لا أثر.
2. **الملفات غير موقّعة رقمياً**، فيظهر تحذير SmartScreen لكل زبون.
   شهادة توقيع OV تحلّها، أو أضف صور تعليمات تشرح الرسالة قبل أن يراها.
3. **بصمة الجهاز** = الرقم التسلسلي للقرص + اسم الجهاز. تغيير اسم الكمبيوتر
   يبطل ترخيصاً مدفوعاً. أضف `MachineGuid` من السجل كمكوّن ثالث، واجعل
   إعادة الإصدار إجراءً معروفاً عندك.
4. **الأرشفة**: بعد سنتين سيصل `store.json` إلى 20–30 ميجابايت. انقل فواتير
   السنوات السابقة إلى ملف أرشيف يُقرأ عند الطلب فقط.
